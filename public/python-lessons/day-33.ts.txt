<b>Deterministic Resource Cleanup and System Resilience</b><br/>
In software development, your application constantly acquires system resources: opening file handles, establishing database sockets, locking hardware mutexes, and connecting to network APIs. <b>1. The Danger of Unclosed System Resources:</b><br/>
Consider a script processing 10,000 package manifest files in a loop. If you open each file manually without closing it, the operating system eventually runs out of available file descriptors and throws a fatal <code>OSError: Too many open files</code> crash!<br/><br/>

<b>2. The Limitations of Manual Cleanup (<code>try/finally</code>):</b><br/>

Python's <code>with</code> statement encapsulates resource acquisition and release into a single, clean, declarative block:<br/>
<code>with open("manifest.csv", "r") as file_handle:</code><br/>

<b>Class-Based Custom Resource Managers</b><br/>
While built-in tools like <code>open()</code> and <code>threading.Lock</code> support the <code>with</code> statement natively, real-world enterprise applications require custom resource managers. To make a custom class compatible with the <code>with</code> statement, you must implement the <b>Context Manager Protocol</b>.<br/><br/>

<b>1. The Context Manager Protocol Dunder Methods:</b><br/>
A class becomes a Context Manager by implementing two special dunder methods:
<ul>
  <li><code>__enter__(self)</code>: Executed **before** code inside the `with` block runs.
    <br/><i>Purpose:</i> Acquires the system resource, initializes state, and optionally returns an object (which is bound to the variable target after <code>as</code>).</li>
  <li><code>__exit__(self, exc_type, exc_val, exc_tb)</code>: Executed **after** code inside the `with` block finishes or crashes.
    <br/><i>Purpose:</i> Performs resource cleanup, flushes buffers, and handles exceptions.</li>
</ul>

<b>2. Understanding <code>__exit__()</code> Exception Parameters:</b><br/>
When execution leaves the `with` block, Python passes three exception arguments to <code>__exit__</code>:
<ul>
  <li><code>exc_type</code>: The exception class (e.g., <code>ValueError</code>), or <code>None</code> if no error occurred.</li>
  <li><code>exc_val</code>: The exception instance object, or <code>None</code>.</li>
  <li><code>exc_tb</code>: The traceback object, or <code>None</code>.</li>
</ul>

<b>3. Suppressing Exceptions in <code>__exit__()</code>:</b><br/>
By default, any exception raised inside a `with` block is re-raised after `__exit__` completes. However, if `__exit__()` explicitly returns <code>True</code>, Python **suppresses the exception**, preventing it from crashing the program! Returning <code>False</code> or <code>None</code> allows the exception to propagate naturally.

class SafeExecutionBoundary:
    """Context Manager that suppresses specified exception types."""

    def __init__(self, ignore_exception_type):
        self.ignore_exception_type = ignore_exception_type

    def __enter__(self):
        print("\n[ENTER] Entering Safe Execution Boundary...")
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):

        return False

    """Simulates a legacy socket class that has a .close() method but no __enter__/__exit__."""
    def __init__(self, host: str):
        self.host = host
        self.is_closed = False

    def fetch_data(self):
        return f"PAYLOAD_FROM_{self.host}"

    def close(self):
        self.is_closed = True
        print(f"  [LEGACY CLOSE] Socket connection to {self.host} closed.")

print("--- BEGINNER: contextlib.closing ---")
legacy_socket = LegacyNetworkSocket("10.0.0.1")

# Wrapping non-context-manager object with closing()
with closing(legacy_socket) as sock:
    payload = sock.fetch_data()
    print("Fetched Payload:", payload)

print("Is legacy socket closed?", legacy_socket.is_closed) # True

class MockDatabaseSession:
    def __init__(self):
        self.staged_changes = []
        self.committed_db = []

    def add(self, item: str):
        self.staged_changes.append(item)
        print(f"  [DB STAGE] Staged change: '{item}'")

    def commit(self):
        self.committed_db.extend(self.staged_changes)
        self.staged_changes.clear()
        print("  [DB COMMIT] All staged changes committed permanently to database.")

    def rollback(self):
        print(f"  [DB ROLLBACK] Reverting {len(self.staged_changes)} uncommitted staged changes!")
        self.staged_changes.clear()


@contextmanager
def database_transaction(db_session: MockDatabaseSession):
    """Context Manager providing atomic database transactions."""
    print("\n[TRANSACTION START] Beginning database transaction...")
    try:
        yield db_session
        # If block completes without errors, COMMIT changes
        db_session.commit()
    except Exception as err:
        # If error occurs inside block, ROLLBACK changes
        print(f"[TRANSACTION FAILURE] Error detected: {err}")
        db_session.rollback()
        raise # Re-raise error after rollback

print("\n--- PATTERN 2: Database Transaction Execution ---")
db = MockDatabaseSession()

# 1. Successful Transaction Test
with database_transaction(db):
    db.add("INSERT INTO orders VALUES ('ORD-101')")
    db.add("UPDATE inventory SET count = count - 1")

print("Committed DB State:", db.committed_db)

# 2. Failed Transaction Test (Rollback)
try:
    with database_transaction(db):
        db.add("INSERT INTO orders VALUES ('ORD-102')")
        raise RuntimeError("Payment gateway timeout!")
except RuntimeError:
    print("Transaction aborted cleanly.")

print("Committed DB State (Uncorrupted):", db.committed_db)
