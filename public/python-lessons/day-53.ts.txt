<b>Decoupling Heavy Computations from HTTP Request/Response Cycles</b><br/>
Web servers (like FastAPI running under Uvicorn) are optimized for low-latency, short-lived HTTP requests ($<200\\text{ ms}$). When an API endpoint needs to perform a long-running, CPU-heavy, or I/O-intensive operation (e.g., generating a complex PDF invoice, encoding a video, sending 10,000 push notifications, or training a machine learning model), executing that task synchronously inside the HTTP handler leads to severe problems:<br/>
1. **HTTP Client Timeouts:** The client browser or client app times out waiting for a response.<br/>
2. **Worker Thread Starvation:** Web server worker threads are blocked, preventing other incoming HTTP requests from being processed.<br/><br/>

The solution is an **Asynchronous Task Queue** architecture.<br/><br/>

<b>1. The Task Queue Topology:</b>
<ul>
  <li><b>Producer (Web API Server):</b> Receives the HTTP request, enqueues a lightweight "Task Message" (containing function arguments) into the broker, returns an immediate <code>HTTP 202 Accepted</code> response to the client, and releases its worker thread!</li>
  <li><b>Message Broker (Redis or RabbitMQ):</b> A high-throughput, persistent queue server that buffers task messages until worker processes consume them.</li>
  <li><b>Consumer / Worker Fleet (Celery Worker Processes):</b> Independent Python background worker processes running on separate servers/containers. They pull task messages from the broker, execute the actual Python code, and store task execution results.</li>
  <li><b>Result Backend (Redis or Database):</b> Stores task execution states (\`PENDING\`, \`STARTED\`, \`SUCCESS\`, \`FAILURE\`) and return values.</li>
</ul>

# LESSON 3: Exponential Backoff and Dead-Letter Queue Logic
# ==============================================================================

import random
import time

def calculate_exponential_backoff(retry_attempt: int, base_delay: float = 2.0, max_delay: float = 300.0) -> float:
    """
    Computes exponential backoff delay with random jitter.
    Formula: Delay = min(max_delay, base_delay * (2 ^ attempt)) + jitter
    """
    calculated_delay = base_delay * (2 ** retry_attempt)
    jitter = random.uniform(0.1, 1.0) # Prevents thundering herd problem
    final_delay = min(max_delay, calculated_delay + jitter)
    return round(final_delay, 2)

    for attempt in range(max_retries + 1):
        try:
            print(f"  Attempt {attempt + 1}/{max_retries + 1}: Executing webhook dispatch...")
            # Simulate intermittent network failure
            if attempt < max_retries:
                raise ConnectionError("503 Service Unavailable: Remote Gateway Down")

            print("  SUCCESS: Webhook delivered successfully.")
            return True

        except ConnectionError as err:
            if attempt < max_retries:
