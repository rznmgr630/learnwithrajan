<b>Indefinite Loops, Loop Controls, and Placeholders</b><br/>
Not all repetitive tasks know their exact iteration count beforehand. A delivery driver app continues scanning package barcodes until the truck is full; a satellite connection retries every 5 seconds until a server ping succeeds. For tasks dependent on dynamic conditions, Python provides the <b><code>while</code> loop</b> alongside explicit loop control statements: <code>break</code>, <code>continue</code>, and <code>pass</code>.<br/><br/>

<b>1. The <code>while</code> Loop (Condition-Driven Iteration):</b><br/>
A <code>while</code> loop repeatedly executes its code block as long as a boolean condition remains <code>True</code>.
<ul>
  <li><b>The Infinite Loop Hazard:</b> If the tested condition never becomes <code>False</code> (or if no internal <code>break</code> statement triggers), the loop runs forever, freezing your program! Always ensure loop state variables are updated within the loop body.</li>
</ul>

<b>2. Loop Control Statements:</b>
<ul>
  <li><b><code>break</code> (Immediate Termination):</b> Instantly aborts the entire loop, skipping all remaining iterations and jumping directly to the first line after the loop.</li>
  <li><b><code>continue</code> (Skip to Next Iteration):</b> Instantly skips the remaining lines inside the current loop body and jumps directly to the top for the next iteration step.</li>
  <li><b><code>pass</code> (Syntactic Placeholder):</b> A no-op statement that does nothing. It acts as a mandatory placeholder where Python syntax requires a code block (e.g., unwritten function stubs or empty exception blocks).</li>
</ul>

<b>3. The Optional <code>else</code> Clause on Loops:</b><br/>
Python loops support a unique <code>else</code> block attached to the end of a <code>for</code> or <code>while</code> loop!
The loop <code>else</code> block executes <b>only if the loop completes all iterations naturally</b> (i.e., without encountering a <code>break</code> statement). If a loop is aborted by <code>break</code>, the <code>else</code> block is completely skipped.

<b>Nested Loops, Matrix Iteration, and $O(N^2)$ Complexity</b><br/>
A **Nested Loop** occurs when you place a loop inside the body of another loop. Nested loops are frequently required when working with multi-dimensional structures, such as iterating over rows and columns of a warehouse storage grid, matching delivery drivers to package batches, or processing multi-hub transportation matrices.<br/><br/>

<b>1. How Nested Loops Work:</b><br/>
For <i>every single iteration</i> of the outer loop, the inner loop executes its entire iteration cycle from start to finish!<br/>
If the outer loop runs $M$ times and the inner loop runs $N$ times, the innermost code block executes $M \times N$ total times.<br/><br/>

<b>2. The Performance Trap: $O(N^2)$ Time Complexity:</b><br/>
A major source of performance degradation in real-world software is uncontrolled nested iteration.
<ul>
  <li>Scanning 100 packages against 100 delivery zones requires $100 \times 100 = 10,000$ operations (instant).</li>
  <li>Scanning 100,000 packages against 100,000 delivery zones in a nested loop requires $100,000 \times 100,000 = 10,000,000,000$ (10 billion) operations, causing your application to freeze!</li>
</ul>

<b>3. Cleaner Alternatives to Nested Loops:</b>
<ul>
  <li><b>`zip(seq1, seq2)`:</b> Iterates over multiple equal-length sequences in parallel simultaneously! Yields `(item1, item2)` tuple pairs in a single clean $O(N)$ loop.</li>
  <li><b>Set Lookups inside Loops:</b> Convert the inner collection to a `set` before the loop. Lookups inside sets run in $O(1)$ time, reducing an $O(N^2)$ nested search to an $O(N)$ linear loop!</li>

def find_flagged_packages_unoptimized(all_packages: list[str], flagged_ids: list[str]) -> list[str]:

def find_flagged_packages_optimized(all_packages: list[str], flagged_ids: list[str]) -> list[str]:
    \"\"\"
    O(N + M) Linear Time Complexity - Convert inner list to set for O(1) lookups!
    \"\"\"
