<b>Fixed-Length, Immutable Data Structures</b><br/>
While lists are designed for dynamic, changing collections where items are constantly appended, deleted, or reordered, software often deals with data that <i>must never change after creation</i>. <b>1. What is a Tuple?</b><br/>
A tuple is an <b>ordered</b>, <b>immutable</b> sequence of values written with parentheses <code>(...)</code> separated by commas.
<ul>
  <li><b>Ordered:</b> Elements maintain exact zero-based index positions (`tuple[0]`).</li>

  <li><b>Single-Element Tuple Syntax Warning:</b> To define a single-element tuple, you MUST include a trailing comma: <code>single_item = ("CHICAGO",)</code>. Writing <code>("CHICAGO")</code> without a comma creates a standard string!</li>
</ul>

<b>2. Why use a Tuple instead of a List?</b>
<ol>
  <li><b>Data Integrity & Safety:</b> Tuples act as a strict contract. Passing a tuple into external functions guarantees that the function cannot accidentally mutate or corrupt your fixed record.</li>
  <li><b>Memory & Performance Optimization:</b> Tuples are more memory-efficient and faster to allocate than lists because Python doesn't need to reserve extra memory buffer space for potential growth.</li>
  <li><b>Dictionary Keys & Set Elements:</b> Because tuples are immutable (and hashable), they can be used as keys inside dictionaries or items inside sets (e.g., `location_map[(41.8781, -87.6298)] = "Chicago Hub"`). Lists can NEVER be used as dictionary keys!</li>
</ol>

<b>Unordered Collections of Unique Elements</b><br/>

<b>1. What is a Set?</b><br/>
A set in Python is an <b>unordered</b>, <b>mutable</b> collection of <b>unique</b>, hashable items written with curly braces <code>{...}</code>.
<ul>
  <li><b>Unordered:</b> Elements have NO fixed index position. You cannot access set items using indexing (<code>set[0]</code> raises a <code>TypeError</code>).</li>
  <li><b>Unique:</b> Duplicate values are automatically discarded upon insertion! Adding `"CHICAGO"` to a set 100 times results in a set containing exactly one `"CHICAGO"`.</li>
  <li><b>Fast $O(1)$ Lookups:</b> Searching if an item exists inside a set (`x in my_set`) executes in constant time $O(1)$, compared to $O(N)$ linear scans in lists.</li>
  <li><b>Empty Set Syntax Warning:</b> To create an empty set, you MUST use the constructor `empty_set = set()`. Writing `empty_dict = {}` creates an empty **dictionary**!</li>
</ul>

<b>2. Set Mathematical Operations:</b><br/>
Sets support powerful mathematical set-theory operations:
<ul>
  <li><b>Union (<code>a | b</code> or <code>a.union(b)</code>):</b> Combines all unique items from both sets.</li>
  <li><b>Intersection (<code>a &amp; b</code> or <code>a.intersection(b)</code>):</b> Returns items present in <b>both</b> sets.</li>
  <li><b>Difference (<code>a - b</code> or <code>a.difference(b)</code>):</b> Returns items in set `a` that are <b>not</b> in set `b`.</li>
  <li><b>Symmetric Difference (<code>a ^ b</code>):</b> Returns items in either set, but <b>not in both</b>.</li>
</ul>
