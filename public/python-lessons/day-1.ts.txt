<b>What is the Python Interpreter and why does it exist?</b><br/>
Computers do not understand human languages, nor do they directly understand Python code. At the hardware level, CPUs only process binary instructions (1s and 0s). Python is a <b>high-level, interpreted programming language</b>. <b>What problem does it solve?</b><br/>
Without an interpreter or compiler, you would have to write raw machine code or assembly language just to display a package status on a screen. The Python interpreter abstracts away hardware complexities like RAM allocation and CPU register management.<br/><br/>

<b>When to use / verify it?</b><br/>

<b>Interacting with Python: REPL vs. Script Files</b><br/>
Once Python is installed, you can interact with it in two distinct ways: through the <b>REPL (Read-Eval-Print Loop)</b> or by executing <b>Script Files (<code>.py</code> files)</b>.<br/><br/>

<b>1. The REPL (Interactive Shell)</b><br/>
When you type <code>python3</code> in your terminal without any arguments, you enter an interactive session indicated by the <code>&gt;&gt;&gt;</code> prompt. 
<ul>
  <li><b>Read:</b> Takes the line of code you type.</li>
  <li><b>Eval:</b> Evaluates/executes the code immediately.</li>
  <li><b>Print:</b> Prints the result to the console.</li>
  <li><b>Loop:</b> Waits for your next input.</li>
</ul>
<b>When to use REPL:</b> Quick calculations, testing a single function or regex pattern, or inspecting library methods.<br/>
<b>When NOT to use REPL:</b> Building real multi-step software. Once you close the REPL session, all code is lost permanently.<br/><br/>

<b>2. Script Files (.py)</b><br/>
For building real applications like our Delivery Status Tracker, code is written in plain text files saved with a <code>.py</code> extension (e.g., <code>tracker.py</code>) and executed using <code>python3 tracker.py</code>.<br/><br/>

<b>Expressions vs. Statements</b><br/>
Understanding the fundamental difference between an expression and a statement is critical for avoiding syntax bugs:
<ul>
  <li><b>Expression:</b> A combination of values, variables, and operators that <i>evaluates to a single resulting value</i>. Example: <code>5 + 10</code> or <code>package_weight * 2.5</code>.</li>
  <li><b>Statement:</b> An instruction that <i>performs an action</i> or controls execution flow, but does not evaluate to a value by itself. Example: variable assignments (<code>status = "SHIPPED"</code>), conditional checks (<code>if / else</code>), or loop constructs.</li>
</ul>

<b>Writing Clean Python Code: Indentation, Comments, and Debugging</b><br/><br/>

<b>1. Indentation as Syntax Structure</b><br/>
Unlike languages such as JavaScript, C++, or Java that use curly braces <code>{}</code> to define blocks of code, <b>Python uses white space indentation</b>.
<ul>
  <li>Standard Python convention (PEP 8) requires <b>4 spaces per indentation level</b>.</li>
  <li>Mixing spaces and tabs causes an immediate <code>IndentationError</code> or <code>TabError</code>.</li>
  <li>An indented block tells Python that certain statements belong inside a function, loop, or conditional block.</li>
</ul>

<b>2. Intentional Commenting</b><br/>
Comments explain <i>WHY</i> code was written a certain way, not just <i>WHAT</i> the code does.
<ul>
  <li><b>Single-line comments:</b> Start with a hash symbol <code>#</code>.</li>
  <li><b>Docstrings (Multi-line comments):</b> Enclosed in triple quotes <code>\"\"\" docstring here \"\"\"</code> at the start of modules, classes, or functions to document usage.</li>
</ul>

<b>3. Basic Debugging Techniques</b><br/>
When your code crashes, Python prints a <b>Traceback</b>. A Traceback tells you:
1. The exact file and line number where the error occurred.
2. The sequence of function calls leading to the error.
3. The specific error type (e.g., <code>NameError</code>, <code>TypeError</code>, <code>SyntaxError</code>, <code>ZeroDivisionError</code>).<br/><br/>

<b>Real-World Logistics Example:</b><br/>
Imagine calculated delivery time equals <code>total_distance / speed</code>. If <code>speed</code> is accidentally set to <code>0</code> (e.g., vehicle breakdown), Python throws a <code>ZeroDivisionError</code>. Learning to read the traceback allows you to instantly fix the line causing the failure.
