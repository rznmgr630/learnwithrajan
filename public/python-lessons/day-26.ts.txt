Counter is one of the most useful tools in collections because counting values is an extremely common programming task.

Suppose you have:

The list here is a factory. When a missing key is accessed, Python creates an empty list automatically.

This is similar to Counter.

deque stands for double-ended queue.

A queue is a data structure where items are normally processed in the order they arrive.

For example, imagine a restaurant.

Customers arrive:

Rajan
Alice
John

The first customer who arrived should normally be served first.

This is called FIFO:

First In, First Out.

A simple Python list can represent a queue:

queue = []

queue.append("Rajan")
queue.append("Alice")
queue.append("John")

Then:

queue.pop(0)

works, but removing the first item from a large list can be inefficient because Python may need to move the remaining elements.

deque is designed specifically for efficient insertion and removal from both ends.

from collections import deque

queue = deque()

queue.append("Rajan")
queue.append("Alice")
queue.append("John")

customer = queue.popleft()

print(customer)

The result is:

Rajan

The queue now contains:

Alice
John

This is useful for real-world systems such as:

- Job queues
- Message processing
- Background task processing
- Web request queues
- Customer service queues
- Breadth-first search
- Recent activity tracking

deque can also work like a stack.

A stack follows LIFO:

Last In, First Out.

stack = deque()

stack.append("A")
stack.append("B")
stack.append("C")

print(stack.pop())

The result is C.

This means the same deque structure can be used for both queue-like and stack-like operations.

deque also supports appendleft():

queue.appendleft("Priority Task")

Now the item is inserted at the beginning.

This can be useful when you have urgent work that should be placed at the front of a processing queue.

Another powerful feature is maxlen.

Suppose your application needs to remember only the last five actions performed by a user.

You could manually remove old items, but deque can do this automatically:

recent_actions.append("add-to-cart")
recent_actions.append("checkout")
recent_actions.append("logout")

This makes bounded deques useful for:

- Recent logs
- Recent requests
- Sliding windows
- Recent searches
- Recent user actions
- Small rolling caches

To understand itertools properly, you first need to understand iterables and iterators.

You have already used objects such as lists:

numbers = [10, 20, 30]

A list is iterable.

That means Python can retrieve its values one by one.

For example:

for number in numbers:
    print(number)

When Python executes a for loop, it internally works with an iterator.

You can create one yourself:

iterator = iter(numbers)

Then retrieve values with next():

print(next(iterator))
print(next(iterator))
print(next(iterator))

The output is:

10
20
30

The iterator remembers where it currently is.

After all values have been consumed:

next(iterator)

raises:

StopIteration

This is how Python knows that the iteration has finished.

The difference between iterable and iterator is important.

An iterable is an object that can provide an iterator.

Examples include:

- list
- tuple
- set
- dictionary
- string
- range

An iterator is an object that keeps track of its current position and produces the next value when requested.

You can think about it like a book.

A list is the complete book.

An iterator is like a bookmark that tells Python where to read next.

This becomes extremely important when working with large data.

Imagine a file containing 10 million lines.

You could load everything:

lines = file.readlines()

Now all 10 million lines may be held in memory.

Instead, you can process the file one line at a time:

for line in file:
    process(line)

The file object provides values progressively.

This is called lazy processing.

Lazy processing means that values are produced when they are needed instead of creating the entire result immediately.

Consider:

numbers = [x * 2 for x in range(1_000_000)]

This creates a list containing one million values.

A generator expression:

numbers = (x * 2 for x in range(1_000_000))

does not create all one million values immediately.

Instead, it produces each value as you request it.

This is particularly useful for:

- Large files
- Database records
- API responses
- Data processing
- ETL pipelines
- Log processing
- Streaming data

The itertools module builds on this idea.

itertools provides functions that create efficient iterators.
