<b>Branching Execution Paths in Python</b><br/>
Programs cannot treat every piece of data identically. In real-world software, code must make decisions and execute different instructions depending on the situation. For example, a delivery tracking app must show different status updates depending on whether a package is <b>In Transit</b>, <b>Out for Delivery</b>, or <b>Delivered</b>. Python handles this decision-making using conditional branching statements: <code>if</code>, <code>elif</code> (short for "else if"), and <code>else</code>.<br/><br/>

<b>1. The <code>if</code> Statement (The Initial Branch):</b><br/>
The <code>if</code> statement checks a boolean condition. If the condition evaluates to <code>True</code>, Python executes the indented block of code directly beneath it. If it evaluates to <code>False</code>, Python completely skips that block.<br/><br/>

<b>2. The <code>elif</code> Statement (Alternative Mutually Exclusive Paths):</b><br/>
When you have multiple mutually exclusive conditions to test sequentially, use <code>elif</code>. Python evaluates <code>elif</code> conditions one by one from top to bottom <b>only if all preceding conditions evaluated to <code>False</code></b>. As soon as Python finds an <code>elif</code> condition that evaluates to <code>True</code>, it executes that branch's block and skips all remaining <code>elif</code> and <code>else</code> branches in that chain!<br/><br/>

<b>3. The <code>else</code> Statement (The Fallback Catch-All):</b><br/>
The <code>else</code> block sits at the very end of a conditional chain. It takes no condition and executes <i>only</i> if every preceding <code>if</code> and <code>elif</code> condition evaluated to <code>False</code>.<br/><br/>

<b>Guard Clauses and Bouncer Pattern</b><br/>
A <b>Guard Clause</b> (also known as the <i>Bouncer Pattern</i>) is a design pattern where a function evaluates invalid or edge-case conditions at the very top of the function and exits early (using <code>return</code> or <code>raise</code>).<br/><br/>

<b>Traditional Nesting vs. Guard Clause Pattern:</b><br/>
In traditional code, developers wrap the entire "happy path" (the main business logic) inside a huge `if` block, putting error handling at the very bottom of the function. Guard clauses flip this structure: handle error cases and invalid inputs first at the top, exit immediately, and leave the rest of the function for the unindented, clean happy path!<br/><br/>

<b>Benefits of Guard Clauses:</b>
1. <b>Eliminates Indentation:</b> Keeps the main happy path execution flat at the root indentation level of the function.
2. <b>Fails Fast:</b> Invalid inputs are caught and rejected immediately before expensive calculations or database queries run.
3. <b>Improves Scannability:</b> Developers can quickly inspect what preconditions a function requires by scanning the top few lines.

def dispatch_package_to_hub(package_id: str, hub_code: str) -> str:

2. The <code>if condition</code> comes SECOND.<br/>

<b>When to Use Conditional Expressions:</b><br/>
- Assigning simple values or flags based on a single condition.<br/>

<b>When NOT to Use Conditional Expressions:</b><br/>
