<b>Extending Function Behavior without Modifying Source Code</b><br/>
When building enterprise software, you frequently need to apply cross-cutting concerns—such as execution timing, authentication checks, audit logging, or input validation—across dozens of different functions. Modifying every single function's internal source code introduces massive code duplication and breaks the Single Responsibility Principle.<br/><br/>

A <b>Decorator</b> is a higher-order function that takes a target function as input, wraps it with additional pre-processing or post-processing behavior, and returns the enhanced wrapped function.<br/><br/>

<b>1. What is a Decorator?</b><br/>
A decorator is simply a wrapper function:<br/>
<pre><code>def my_decorator(func):
    def wrapper():
        print("Before function call...")
        func() # Execute original target function
        print("After function call...")
    return wrapper</code></pre><br/>

<b>Decorators Without Metadata Identity Loss</b><br/>
When you decorate a function, Python rebinds the target function name to the inner `wrapper` function object. While this gives you powerful wrapping behavior, it introduces a subtle, serious bug: **Function Metadata Identity Loss**.<br/><br/>

<b>1. The Metadata Loss Problem:</b><br/>
Without metadata preservation, inspecting a decorated function reveals that its original name (<code>__name__</code>) and docstring (<code>__doc__</code>) have been overwritten by the wrapper function!<br/>
<code>@my_decorator</code><br/>
<code>def dispatch_parcel():</code><br/>
<code>    """Dispatches a parcel."""</code><br/>
<code>    pass</code><br/><br/>
<code>print(dispatch_parcel.__name__) # Outputs 'wrapper', NOT 'dispatch_parcel'!</code><br/>
<code>print(dispatch_parcel.__doc__)  # Outputs None, losing original documentation!</code><br/><br/>

<b>Why is this a problem?</b>
<ul>
  <li>Breaks introspection tools, auto-generated documentation generators (like Sphinx/FastAPI), and step-through debuggers.</li>
  <li>Breaks unit test suites relying on function names.</li>
</ul>

To make a decorator accept arguments, you create a **Decorator Factory**—a function that accepts arguments and returns a standard decorator!<br/>

<code>@require_role("ADMIN")</code><br/>
<code>def delete_record(): pass</code><br/><br/>

<code>decorator = require_role("ADMIN") # Call factory to get decorator</code><br/>
<code>delete_record = decorator(delete_record) # Decorate function</code>

from functools import wraps
import time

# ------------------------------------------------------------------------------
# Beginner: 3-Level Decorator Factory for Configurable Retries
# ------------------------------------------------------------------------------

# Level 1: Outer Factory accepts configuration parameters
def retry_on_failure(max_retries: int = 3, delay_sec: float = 0.1):
    """Decorator Factory creating configurable retry wrappers."""
    # Level 2: Middle function accepts target function
    def decorator(func):
        # Level 3: Inner wrapper accepts function runtime arguments
        @wraps(func)
        def wrapper(*args, **kwargs):
            attempts = 0
            while attempts < max_retries:
                try:
                    attempts += 1
                    return func(*args, **kwargs)
                except Exception as err:
                    print(f"  [RETRY] Attempt {attempts}/{max_retries} failed for '{func.__name__}': {err}")
                    if attempts >= max_retries:
                        raise # Re-raise exception when retries exhausted
                    time.sleep(delay_sec)
        return wrapper
    return decorator

        unstable_network_ping.calls = 0
    unstable_network_ping.calls += 1

    if unstable_network_ping.calls < 2:
