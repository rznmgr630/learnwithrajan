<b>Managing In-Memory Object State Changes</b><br/>
In SQLAlchemy ORM, database operations do not execute immediately when you modify a Python object property. Instead, object instances are tracked inside a **Session** using the **Unit of Work** design pattern.<br/><br/>

<b>1. The Session (Unit of Work Manager):</b><br/>
The <code>Session</code> tracks changes made to mapped Python objects (new insertions, property updates, deletions) in memory. It holds these staged changes until you explicitly commit the session.<br/><br/>

<b>2. The Entity Lifecycle States:</b>
<ul>
  <li><b>Transient:</b> Object instantiated in Python (`pkg = ParcelRecord(...)`), but not yet attached to a Session or saved in the DB.</li>
  <li><b>Pending:</b> Object added to a Session (`session.add(pkg)`), but not yet flushed to the database.</li>
  <li><b>Persistent:</b> Object flushed and saved in the database; tracked actively by the Session.</li>
  <li><b>Detached:</b> Object exists in RAM with database keys, but its Session was closed.</li>
</ul>

<b>3. Automatic Flush on Commit:</b><br/>
When you execute <code>session.commit()</code>:
<ol>
  <li>The Session automatically **flushes** all staged changes, generating and executing `INSERT`, `UPDATE`, and `DELETE` SQL statements in an atomic transaction.</li>
  <li>If successful, it commits the database transaction.</li>
</ol>
      `,

  [ Flushed & Committed ]         ---> PERSISTENT (Saved in DB, ID assigned)
