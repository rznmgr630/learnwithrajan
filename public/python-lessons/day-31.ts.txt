<b>Under the Hood of Python's Iteration Protocol</b><br/>
Every Python developer uses <code>for</code> loops daily, but few understand the underlying low-level mechanisms powering them. How does Python step through a 100,000-item list, a dictionary, or a file object without crashing? The answer lies in the formal distinction between <b>Iterables</b> and <b>Iterators</b>.<br/><br/>

<b>1. What is an Iterable?</b><br/>
An <b>Iterable</b> is any Python object capable of returning its members one at a time. Lists, tuples, sets, dictionaries, and strings are all Iterables.
<ul>
  <li><b>Key Characteristic:</b> An Iterable implements the <code>__iter__()</code> dunder method. Passing an Iterable to <code>iter(obj)</code> returns a brand-new **Iterator** object.</li>
  <li><b>Analogy:</b> An Iterable is like a physical <b>book</b> resting on a shelf. The book contains pages, but it does not track which page you are currently reading.</li>
</ul>

<b>2. What is an Iterator?</b><br/>
An <b>Iterator</b> is a stateful stream object that remembers its current position during traversal.
<ul>
  <li><b>Key Characteristic:</b> An Iterator implements the <code>__next__()</code> dunder method. Calling <code>next(iterator)</code> fetches the next sequential item from the stream and advances the internal pointer.</li>
  <li><b>StopIteration Exception:</b> When no more items remain in the stream, calling <code>next(iterator)</code> raises a <code>StopIteration</code> exception. This exception signals to loops that traversal is complete!</li>
  <li><b>Analogy:</b> An Iterator is like a <b>bookmark</b> placed inside that book. It tracks exactly which page comes next and advances page-by-page as you read.</li>
</ul>

<b>3. How a <code>for</code> Loop Works Internally:</b><br/>
When you write <code>for item in my_list:</code>, Python executes this exact low-level process under the hood:
<ol>

  <li>Enters an infinite loop calling <code>item = next(it)</code> on every step.</li>
  <li>Catches the <code>StopIteration</code> exception silently and exits the loop cleanly!</li>

<b>Stateful Streaming Functions without Memory Bloat</b><br/>

<b>1. What is a Generator Function?</b><br/>
A Generator Function looks like a standard Python function, but instead of using <code>return</code> to send back a single final value and terminate, it uses the <code>yield</code> keyword.<br/>
<code>def package_stream():</code><br/>
<code>    yield "TRK-101" # Pauses execution and returns "TRK-101"</code><br/>
<code>    yield "TRK-202" # Resumes execution, yields "TRK-202", and pauses again!</code><br/><br/>

<b>2. How <code>yield</code> Works (The Execution Pause & Resume Mechanism):</b>
<ul>
  <li>When a generator function is called, <b>none of its code runs immediately</b>. Instead, it returns a special **Generator Object** (which is a specialized Iterator).</li>
  <li>When <code>next(generator)</code> or a <code>for</code> loop requests a value, execution runs until it hits a <code>yield</code> statement.</li>

  <li>On the next <code>next()</code> call, execution resumes immediately at the line *after* the <code>yield</code> statement, preserving all local variable states!</li>
</ul>

The printer sits idle (using no extra paper or desk space) until the next page is requested.
