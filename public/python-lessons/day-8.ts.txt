<b>Key-Value Association & Hash Table Fundamentals</b><br/>
In real-world applications, data is rarely stored as an unindexed sequence of standalone values. <b>1. What is a Dictionary?</b><br/>
A dictionary in Python is an <b>ordered</b>, <b>mutable</b> mapping of <b>unique, hashable keys</b> to arbitrary values, written with curly braces <code>{key: value}</code>.
<ul>
  <li><b>Keys:</b> Act as unique identifiers (labels). Keys must be <b>immutable/hashable</b> types (e.g., <code>str</code>, <code>int</code>, <code>float</code>, <code>tuple</code>). You can <i>never</i> use a mutable object like a <code>list</code> or another <code>dict</code> as a key!</li>
  <li><b>Values:</b> The data associated with each key. Values can be anything: integers, floats, strings, lists, nested dictionaries, or custom objects.</li>
  <li><b>Fast $O(1)$ Lookup Speed:</b> Under the hood, Python dictionaries use a <b>hash table</b>. Reading a value by key (`package["status"]`) takes constant time $O(1)$ regardless of whether the dictionary contains 10 key-value pairs or 10,000,000!</li>
</ul>

<b>2. Accessing Keys Safely: Bracket Notation vs. `.get()`</b><br/>
Understanding how to handle missing keys separates beginner code from production-ready code:
<ul>
  <li><b>Bracket Lookup (<code>dict[key]</code>):</b> Reads the value associated with `key`. <b>Danger:</b> If `key` does not exist in the dictionary, Python raises an unhandled <code>KeyError</code> crash!</li>
  <li><b>Safe Lookup (<code>dict.get(key, default)</code>):</b> Searches for `key`. If found, it returns the value. If missing, it safely returns <code>None</code> (or a custom default value like `"UNKNOWN"`) without crashing.</li>
