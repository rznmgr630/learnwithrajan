<b>Isolating Unit Tests from External System Dependencies</b><br/>
Real-world logistics software depends on external systems: credit card payment gateways, cloud database servers, SMS notification APIs, and third-party GPS webhooks. If your unit tests execute actual network requests or write real rows to a live production database, your tests become slow, flaky, dependent on internet connectivity, and dangerous to execute.<br/><br/>

<b>1. The Test Double Taxonomy (Mocks, Stubs, Spies, Fakes, Dummy):</b>
<ul>
  <li><b>Dummy:</b> An object passed around but never actually used or called.</li>
  <li><b>Stub:</b> Provides hardcoded canned responses to function calls during tests (e.g., returning <code>{"status": "OK"}</code> without hitting a server).</li>
  <li><b>Spy:</b> A stub that records information about how it was called (recording argument histories and call counts).</li>
  <li><b>Fake:</b> A working lightweight implementation unsuitable for production (e.g., an in-memory SQLite database replacing PostgreSQL).</li>
  <li><b>Mock:</b> A configurable test double object expecting specific calls, arguments, and invocation counts, failing the test if unexpected calls occur.</li>
</ul>

<b>2. Python's Built-in <code>unittest.mock.Mock</code> & <code>MagicMock</code>:</b><br/>
Python provides the <code>unittest.mock</code> module. A <code>Mock</code> object intercepts any method or attribute access dynamically, returning a new Mock automatically.<br/>
<code>MagicMock</code> inherits from <code>Mock</code> and implements default dunder method implementations (e.g., <code>__len__</code>, <code>__getitem__</code>, <code>__iter__</code>).<br/><br/>

<b>3. Inspecting Mock Calls and Assertions:</b>
<ul>
  <li><code>mock_obj.assert_called_once()</code>: Asserts the mock was called exactly 1 time.</li>
  <li><code>mock_obj.assert_called_with("TRK-1001", priority="HIGH")</code>: Asserts the mock's most recent call matched exact parameters.</li>
  <li><code>mock_obj.return_value = 150.0</code>: Configures a hardcoded return value.</li>
  <li><code>mock_obj.side_effect = ConnectionError("Gateway Timeout")</code>: Configures the mock to raise an exception when called!</li>
</ul>

<b>Intercepting Module-Level Imports and System Environment State</b><br/>
Configuring mock objects as parameter inputs works when dependencies are passed in explicitly (Dependency Injection). However, legacy or production code often imports dependencies directly at the module level:<br/>
<code>import requests # Inside source file dispatch.py</code><br/>
<code>def sync_data(): response = requests.get("https://api.com")</code><br/><br/>

To isolate tests when target modules import dependencies directly, you must **patch** the module lookup table temporarily during test execution.<br/><br/>

<b>1. The Golden Rule of Patching: "Patch Where an Object is USED, Not Where it is DEFINED!"</b><br/>
Suppose module `A.py` defines `class ShippingAPI`, and module `B.py` imports it: `from A import ShippingAPI`.
<ul>
  <li><b>WRONG:</b> `@patch("A.ShippingAPI")` — Module `B` has already imported its own reference!</li>
  <li><b>RIGHT:</b> `@patch("B.ShippingAPI")` — Patches the reference inside module `B` where it is actually used!</li>
</ul>

<b>2. Patching with <code>unittest.mock.patch</code>:</b>
<ul>
  <li><b>As a Decorator:</b> <code>@patch("dispatch.requests.get")</code> passes the generated mock into the test function as an argument.</li>
  <li><b>As a Context Manager:</b> <code>with patch("dispatch.requests.get") as mock_get:</code> patches for the duration of the block.</li>
</ul>

<b>3. Light-Weight State Patching with pytest's <code>monkeypatch</code> Fixture:</b><br/>
pytest provides a built-in <code>monkeypatch</code> fixture ideal for modifying environment variables, system paths, or dictionary configurations temporarily during a test run:<br/>
<code>monkeypatch.setenv("LOGISTICS_API_KEY", "MOCK_TEST_KEY_99")</code><br/>
<code>monkeypatch.setattr("dispatch.MAX_RETRIES", 1)</code><br/>
When the test function exits, `monkeypatch` automatically restores the original environment variables and attributes!
