<b>Automating Software Delivery Lifecycles via Declarative Workflows</b><br/>
Continuous Integration (CI) and Continuous Deployment (CD) pipelines automate quality gates—linting, static type checking, automated testing, container builds, and deployment release verification—on every code commit.<br/><br/>

<b>GitHub Actions</b> uses declarative YAML files stored inside the <code>.github/workflows/</code> directory to execute automated pipelines upon specific repository events.<br/><br/>

<b>1. Core Terminology & Topology:</b>
<ul>
  <li><b>Workflow:</b> The root automated process composed of one or more jobs defined in a YAML file (e.g., <code>.github/workflows/cicd.yml</code>).</li>
  <li><b>Event (Triggers):</b> Repository conditions that trigger a workflow run (e.g., <code>on: push: branches: [main]</code> or <code>pull_request</code>).</li>
  <li><b>Job:</b> A collection of sequential steps executing on an isolated runner VM environment (e.g., <code>runs-on: ubuntu-latest</code>). Jobs run in <b>parallel</b> by default unless chained with <code>needs</code>!</li>
  <li><b>Step:</b> An individual task command (<code>run: pytest</code>) or pre-built action (<code>uses: actions/checkout@v4</code>).</li>
  <li><b>Runner:</b> An isolated virtual machine or container executing workflow jobs.</li>
</ul>
