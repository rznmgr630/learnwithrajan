<b>High-Concurrency Non-Blocking I/O in Single-Threaded Python</b><br/>
In traditional **Synchronous Execution**, Python executes statements sequentially. When a synchronous function performs network I/O or a database query (e.g., waiting 500 ms for an HTTP response), the executing thread **blocks** completely. The CPU sits idle during I/O waiting periods, unable to process other tasks.<br/><br/>

**Asynchronous Execution (Concurrency via I/O Multiplexing)** allows a single thread to pause an active task during I/O waiting periods and switch execution context to process other pending tasks in parallel.<br/><br/>

<b>1. The Heart of Async: The Event Loop:</b><br/>
The **Event Loop** is an infinite loop that manages and distributes execution time across pending asynchronous tasks.
<ul>
  <li>When Task A hits an I/O operation (e.g., waiting for database results), it pauses itself and yields control back to the Event Loop.</li>
  <li>The Event Loop instantly picks up Task B and executes it.</li>
  <li>When Task A's database I/O completes, the Event Loop resumes Task A right where it paused!</li>
</ul>

<b>Real-World Logistics Analogy: Short-Order Kitchen Chef vs. Slow Cook:</b><br/>
Imagine a restaurant kitchen. A **synchronous chef** places a burger on the grill and stands still for 5 minutes staring at it until it cooks, refusing to take new orders. An **asynchronous chef** places the burger on the grill, sets a timer, immediately turns to chop vegetables for a second order, plates a third order, and returns to flip the burger the moment the timer rings!

<b>Defining, Instantiating, and Awaiting Coroutine Objects</b><br/>
To write asynchronous code in modern Python, you use the keywords <b><code>async</code></b> and <b><code>await</code></b>.<br/><br/>

<b>1. What is a Coroutine?</b><br/>
Declaring a function with <code>async def</code> turns it into a **Coroutine Function**:<br/>
<code>async def fetch_status(): return "OK"</code><br/>
Calling a coroutine function directly (`coro = fetch_status()`) **does NOT run the code immediately!** Instead, it creates and returns a **Coroutine Object**.<br/><br/>

<b>2. The `await` Keyword:</b><br/>
The <code>await</code> keyword pauses execution of the current coroutine until the awaited task yields a result, allowing the Event Loop to run other tasks in the meantime.<br/>
<code>result = await async_database_query()</code><br/><br/>

<b>3. Crucial Rule of `await`:</b><br/>
You can **ONLY** use `await` inside functions declared with `async def`! Attempting to use `await` inside a standard synchronous `def` function raises a `SyntaxError`.

<b>Managing Multi-Task Execution Trees</b><br/>
Executing coroutines one-by-one with `await coro1()`, `await coro2()` runs them sequentially, negating async concurrency benefits. To achieve real concurrency, you must schedule coroutines on the Event Loop as **Tasks**.<br/><br/>

<b>1. `asyncio.create_task()`:</b><br/>
Schedules a coroutine to run concurrently on the Event Loop in the background immediately:<br/>
<code>task1 = asyncio.create_task(async_fetch("TRK-101"))</code><br/>
<code>task2 = asyncio.create_task(async_fetch("TRK-102"))</code><br/>
<code>res1 = await task1</code><br/>
<code>res2 = await task2</code><br/><br/>

<b>2. `asyncio.gather()`:</b><br/>
Combines multiple coroutines or tasks into a single awaitable group, running them all concurrently and returning their results in exact order:<br/>
<code>results = await asyncio.gather(coro1(), coro2(), coro3())</code><br/><br/>

<b>3. Handling Exceptions in `gather()`:</b>
<ul>
  <li><code>return_exceptions=False</code> (Default): The first exception raised by any task immediately cancels the gather block and raises the exception to the caller.</li>
  <li><code>return_exceptions=True</code>: Exceptions are caught and returned as objects in the results list alongside valid outputs!</li>
</ul>
