<b>The Protocol of the Modern Web</b><br/>
Hypertext Transfer Protocol (HTTP) is the foundational stateless request-response protocol powering modern web applications and microservice architectures. Client applications (mobile apps, backend services, web browsers) send an **HTTP Request** to a server, and the server processes the payload and returns an **HTTP Response**.<br/><br/>

<b>1. Anatomy of an HTTP Request:</b>
<ul>
  <li><b>HTTP Method (Verb):</b> Indicates the desired action to perform.

      <li><code>PATCH</code>: Partially updates specific fields on an existing resource (Non-Idempotent).</li>

  <li><b>Body (Payload):</b> The optional data content sent with `POST`, `PUT`, or `PATCH` requests.</li>

<b>Consistent, Self-Documenting Error Communication</b><br/>

<b>1. The RFC 7807 Standard (Problem Details for HTTP APIs):</b><br/>
IETF **RFC 7807** defines a standardized, machine-readable JSON schema for conveying API error details using <code>Content-Type: application/problem+json</code>.<br/><br/>

<b>2. RFC 7807 JSON Error Schema Fields:</b>
<ul>
  <li><code>type</code> (URI): A URI reference identifying the specific error type (e.g., <code>"https://api.logistics.com/errors/insufficient-capacity"</code>).</li>
  <li><code>title</code> (str): A short, human-readable summary of the error type.</li>
  <li><code>status</code> (int): The HTTP status code (e.g., <code>400</code>, <code>404</code>, <code>422</code>).</li>
  <li><code>detail</code> (str): A human-readable explanation specific to this occurrence of the error.</li>
  <li><code>instance</code> (URI): A URI reference identifying the specific occurrence of the error (e.g., request log ID).</li>
  <li><code>invalid_params</code> (list - optional): Field-level validation error details.</li>
</ul>
