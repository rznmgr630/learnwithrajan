<b>Container Orchestration Engine Architecture</b><br/>
While Docker packages applications into portable container images, **Kubernetes (K8s)** is the open-source container orchestration engine that manages, scales, heals, and network-routes container fleets across large cluster nodes.<br/><br/>

<b>1. The Atomic Unit: What is a Pod?</b><br/>
A **Pod** is the smallest deployable atomic object in Kubernetes.
<ul>
  <li>A Pod wraps one or more co-located containers (e.g., a FastAPI application container + a sidecar logging agent container) that share the same IP address, network namespace, and storage volumes.</li>
  <li>*Rule:* Pods are ephemeral! Kubernetes can kill, reschedule, or move Pods across cluster worker nodes at any instant. Never write code that assumes a Pod's IP address is permanent.</li>
</ul>

<b>Stable Abstraction Layers for Network Routing and Service Discovery</b><br/>
Because Pods are ephemeral and receive dynamic IP addresses every time they restart, frontend clients cannot connect directly to Pod IPs. **Kubernetes Services** provide persistent IP addresses, DNS hostnames, and layer-4 load balancing across matching Pod sets.<br/><br/>

<b>1. The Four Kubernetes Service Types:</b>
<ul>
  <li><b>ClusterIP (Default - Internal Only):</b> Exposes the Service on an internal cluster IP address. Reachable *only* from within the Kubernetes cluster. Ideal for internal microservices and database pods!</li>
  <li><b>NodePort (Exposes Static Port on Worker Nodes):</b> Opens a static port ($30000\text{--}32767$) on every Kubernetes worker node's physical IP address.</li>
  <li><b>LoadBalancer (Cloud Provider Integration):</b> Requests an external cloud load balancer (e.g. AWS Network Load Balancer or Application Load Balancer) from AWS/GCP/Azure, routing public traffic directly into the Service.</li>
  <li><b>Ingress Controller (Layer 7 HTTP/HTTPS Router):</b> Operates as an edge router (e.g. Nginx Ingress Controller) managing SSL/TLS termination, path-based routing (<code>/api/v1</code> $\rightarrow$ Service A, <code>/auth</code> $\rightarrow$ Service B), and virtual host routing under a single public IP!</li>
